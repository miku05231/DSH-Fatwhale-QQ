## 已确认与已修复

当前树未发现已跟踪的真实配置、凭据、会话或日志文件。Gitleaks 的唯一候选是 `tests/companion-test.mjs` 中用于本地 HTTP 测试夹具和授权断言的合成 TOKEN，经用途核实排除为测试夹具，并非真实凭据。其他合成测试密钥同样按测试上下文处理。

公开导出工具原先保留了两条特定第三方路由域名的检测字面量。本次从 `tools/export-public.mjs` 与对应测试移除了这些路由名称，保留本机目录替换，改用通用的密钥格式和 URL 内嵌长凭据规则。域名名称残留不等于账号或密钥泄漏。

原先检测失败时会把匹配值写入日志，命中真实密钥就可能再次暴露到终端或 CI 日志。本次改为仅记录文件和类别，新增合成密钥及 URL 长凭据负向测试，验证导出拒绝且日志不回显凭据。

原先的成功提示与测试说明声称排除了 QQ 号等内容，超出了实际规则覆盖范围。本次将说明收窄到实际检查项，并明确 QQ 号及其他隐私需要另行审查。

`node tests/export-public-test.mjs` 通过 64 项、失败 0 项，包含验证报告完整导出检查；
相关修改的 `git diff --check` 通过。

## 方法与限制

审计结合了全历史 Git 对象扫描、Gitleaks、人工上下文判读和图片检查。DeepSeek 复核只接收脱敏的类别与代码行为摘要，没有发送候选原值、个人邮箱、账号或私人端点。

覆盖范围不包括不可达对象、其他 PR 引用、分叉仓库、托管平台缓存和既有发布包。模式检测无法保证识别编码、拆分或未知格式的秘密；人工图片检查也不能代替完整的隐写分析。

结论是：在所述范围内未确认真实访问密钥泄漏，已修复导出器的隐私检查和日志问题；
四项历史身份信息与未决标识已在清理副本中替换，其他历史残留与平台副本限制仍如上所述。
