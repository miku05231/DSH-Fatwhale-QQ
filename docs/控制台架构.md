# 控制台架构与功能扩展

本文说明 v3.3 候选的控制台、DSH 连伴插件和现有消息插件。发布与验证状态见 [v3.3.0 验证记录](releases/v3.3.0-verification.md)；旧版结果不能替代本候选的复验。

部署主线是 NapCat（可在 Docker 中运行）经 OneBot WebSocket 连接宿主的 DSH／桥接插件。DSH 保持运行，插件管理桥接与两种控制台；本版不安排桥接或 DSH 的容器化部署。容器与宿主之间的连接地址应填写宿主实际可达的 NapCat 映射地址。

## 运行方式与生命周期

控制台有两个入口，共用同一套前端和 API：

- **独立控制台**：运行 `node src/webui/server.mjs`，默认监听 `127.0.0.1:5830`，供独立启动器、托盘和浏览器使用。
- **DSH 插件页**：完整安装并启用 `qq-bridge-companion` bundle 后，在宿主的同源 `/qq-bridge/` 路径挂载控制台。Desktop 的 `dsh-app://app/` 请求由原生壳转发，不需要改成跨源 HTTP iframe。

```text
DSH Web / Desktop
  └─ qq-bridge-companion
      ├─ 等待 webServer + connection → 挂载 /qq-bridge/*
      ├─ embedded bridge → 宿主进程内消息核心 → NapCat → QQ
      └─ 打开完整版 → 本机临时 HTTP 入口 → 系统默认浏览器

旧版独立运行 server.mjs → 本机完整控制台（非插件主流程）
```

完整 bundle 在插入组件时明确设置 `runMode: embedded`，通过 `createEmbeddedBridge` 在 DSH 宿主进程内启动同一套消息核心，启用后自动连接 NapCat，不 spawn 独立桥接。管理员请求直接进入现有宿主 prompt 处理器；普通成员仍保留 chat-only 子进程与原权限边界。旧独立入口未指定模式时仍按 `standalone` 兼容。

控制器合并并发启停，并回收取消后迟到的启动句柄；停止会取消活动请求、关闭 OneBot 和定时任务，不注册宿主进程级退出处理器。停止后的旧请求不得重新写活状态 PID。启动失败只更新桥接状态，不结束 DSH。

插件控制台通过 `ctx.inject(['webServer', 'connection'], ...)` 跟随宿主 Web 服务的生命周期。服务迟到时等待，服务可用后注册路由；服务撤销时清理对应路由与控制台资源，异步初始化取消后不能发布失效路由。共享桥接控制器由插件管理，插件卸载时统一停止桥接并释放资源。无 Web 服务的宿主仍可使用 companion 会话能力。

源码根与数据根应明确区分：源码根用于加载模块和静态资源；显式 `configFile` 用于定位真实配置及其数据目录。不要为解决路径错误复制或覆盖用户的配置、人格、记忆和状态。

### 完整 bundle 与旧安装脚本

完整插件包位于 `src/companion/`，v3.3 对应 companion `0.3.0`。包通过 `cordis.patch.yml` 插入唯一的 `qq-bridge-companion` 组件，同时导出客户端入口。Desktop 使用原生插件管理器安装本地目录并启用；Web 使用对应 profile 的插件管理功能。安装步骤见 [README](../README.md)。

旧命令 `node tools/install-companion.mjs` 只向 profile 写入服务端 file-URL 补丁，不等于安装了完整客户端 bundle。已有该标记块时，应迁移为同一组件的配置覆盖，避免重复插入；保留 `projectRoot`、`configFile`、`workspacePath` 与 `sessionMapPath` 的有效值，并明确添加 `runMode: embedded`。

## 双模式界面

`?mode=embed` 强制紧凑模式，`?mode=full` 强制完整模式。没有显式模式时，iframe 内默认紧凑，独立页面默认完整；显式参数优先于是否处于 iframe。

| 模式 | 页面与交互 |
| --- | --- |
| 内嵌 | 一个标题栏、桥接状态和启停/重启、打开完整版、三张只读服务卡、统计、人格/模型/表情快捷设置，以及约 6–8 行日志 |
| 完整 | 保留概览、记忆、表情、人格、会话、模型、插件、自动化、系统九页；支持 hash 深链 |

规范 hash 为 `#overview`、`#memory`、`#stickers`、`#persona`、`#sessions`、`#model`、`#plugins`、`#automation`、`#system`。`#memes` 兼容跳转到 `#stickers`。

DSH 插件外层只保留 iframe，避免重复标题、状态栏与启停按钮。子页用 `ResizeObserver` 报告高度；父页仅接受该 iframe 的 `contentWindow` 发出的有效高度消息，并校验数值范围。日志区独立滚动，窄屏页面由宿主滚动。浅色/深色跟随系统，操作按钮常显，并保留键盘和标签支持。

### 状态、动作与快捷设置

| 功能 | 接口 | 生效语义 |
| --- | --- | --- |
| 概览和统计 | `GET /api/overview` | 展示进程、连接与队列等汇总；磁盘状态可能滞后 |
| 桥接实际启停状态 | `GET /api/bridge` | 以专用控制器状态决定 HUD 按钮是否可用 |
| 桥接启动/停止 | `POST /api/bridge/start`、`POST /api/bridge/stop` | 只操作桥接；重启按停止完成后再启动，异步启动完成后返回状态 |
| 全局默认人格 | `GET /api/personas`、`PUT /api/personas/active {name}` | 选择即保存；已有群/会话专属人格仍优先 |
| 模型目标 | `GET /api/model`、`PUT /api/model` | 支持跟随/手动、供应商、模型与思考强度；点击应用后保存，下一次实际出队时生效 |
| 表情自动发送概率 | `GET /api/settings`、`PUT /api/settings` | 仅提交 `stickers.sendProbability`（0–1）；0 暂停自动发送，不改全库开关或自动收集设置 |
| 打开完整控制台 | `POST /api/console/open {page}` | page 只接受九个规范页名；由后端打开系统默认浏览器 |

模型界面分别显示保存目标、待生效/应用失败以及最近实际使用的模型。切回跟随保留已有手动值；运行中的请求不切换模型。轮询不能覆盖尚未点击应用的草稿，保存失败应保留草稿并显示错误。

表情概率允许已有的小数值，未编辑直接保存不应改变精度。表情库整体关闭时，快捷区说明原因并提供完整设置入口；不把启用整个表情库混同于恢复自动发送。

完整界面保留旧的维护接口 `/api/service/<name>/<action>`。插件的桥接动作也转给同一专用控制器，避免误用 Windows ProcessControl 结束 DSH 宿主；无插件控制器的旧独立控制台保留原流程。NapCat／DSH 维护动作仍可能停止共享协议端或整个宿主，内嵌 HUD 的两张卡只读。

### 日志

日志视图按当前来源读取并轮询，支持自动跟随、手动刷新、复制可见内容和清空显示。手动向上滚动会暂停跟随。清空只改变当前视图，并从当前尾部继续接收新行；不删除磁盘日志，不把下一次轮询读到的旧行重新填回。来源切换、文件轮转和错误状态应分别处理。

记忆反思、会话维护、自动化、AstrBot 管理等功能留在完整界面。“用 Obsidian 打开”是现有的打开操作，不代表新增了同步引擎。

## 路径与访问边界

静态 HTML 通过惰性的 `<meta name="qq-bridge-base">` 传递挂载前缀，页面、AstrBot 管理和图片预览使用同一前缀。属性值和资源前缀必须进行 HTML 转义，替换时不能展开 `$&` 等替换元字符。脚本保持 `script-src 'self'`，不依赖内联全局变量或放宽脚本 CSP。

插件路由先通过 DSH 的连接鉴权，并拒绝跨站请求。保留的独立控制台管理操作核对真实回环连接与匹配的 Host；其他既有入口仍执行控制台口令或受信网关断言校验。不能把“只检查 Host”或“控制台无鉴权”当作当前实现。当前部署边界见 [NapCat 与宿主插件](Docker部署.md)。

从插件页打开浏览器完整版时：

1. 后端只接受白名单页名，在 `127.0.0.1` 随机端口创建或复用本机入口；不启动第二个桥接或重复的健康/更新管理器。
2. 浏览器经授权引导页兑换有效期 60 秒、一次性使用的 fragment grant，随后移除授权片段。
3. 兑换后使用有效期 8 小时的 HttpOnly、SameSite=Strict 会话 Cookie，继续校验 Host、Origin 与写操作的请求边界。
4. 宿主作用域销毁时关闭本机监听并撤销会话。不会把 DSH 宿主 Cookie 或认证令牌导出给系统浏览器。

该入口用于本机访问，不扩展远程/NAS 登录方式，也不接受调用者提供任意 URL 或命令。普通成员的聊天权限与管理员电脑工具权限仍由原有权限链分别控制；浏览器进入控制台不会授予 QQ 账号管理员能力。

## 消息插件与扩展

`src/plugins/` 中的消息插件与 DSH 的 `qq-bridge-companion` bundle 是两种不同的扩展。消息插件按文件名加载，`_*.js` 可用于不加载的草稿。

```js
export const meta = {
  name: 'ping',
  displayName: 'Ping',
  version: '1.0.0',
  description: '收到 /ping 时回复',
  defaultEnabled: false,
  configSchema: [
    { key: 'reply', type: 'string', label: '回复', default: 'pong' },
  ],
};

export async function onMessage(ctx) {
  if (ctx.text !== '/ping') return;
  await ctx.reply(ctx.config.reply);
  return { handled: true };
}
```

| 钩子 | 时机 | 返回值 |
| --- | --- | --- |
| `onMessage` | 消息通过准入与唤醒判定后、调用模型前 | `{handled:true}` 接管；`{text:'...'}` 改写；不返回则继续 |
| `beforeReply` | onMessage 之后、构造模型输入之前 | 同上 |
| `afterReply` | 模型回复后、发往 QQ 前 | `{text:'...'}` 改写回复 |

插件上下文包含当前文本、消息与会话来源、`reply`、`log`、合并后的 `config` 和 `meta`。插件按文件名排序，前一个输出交给后一个；异常记日志后跳过。钩子在原有准入后执行，不替代管理员授权；本机 JavaScript 插件是受信代码，插件 API 不是对恶意代码的安全沙箱。

`configSchema` 使用现有 `string`、`text`、`secret`、`bool`、`int`、`select` 字段，控制台据此生成表单。开关在状态目录的 `plugins.json`，配置在 `config.json` 的 `plugins.<name>`；扫描和保存不代表桥接热重载，需按页面提示重启桥接。AstrBot 的独立运行时及群授权另见 [AstrBot 插件说明](astrbot.md)。

新增只读功能时，先在 `src/webui/server.mjs` 增加接口，再由 `index.html` 的 `section.page[data-page]` 和 `app.js` 的页面表/刷新函数接入。新增消息行为优先使用现有钩子；涉及宿主或进程生命周期时，使用对应控制器和作用域清理，不能借旧服务按钮绕过生命周期。
