## 共享磁盘与验收边界

OneBot 文件 URL 由 NapCat 解析。桥接能读取一个文件，不代表另一个容器能按同一路径读取它。
部署时应把同一宿主目录挂载给双方，并传 NapCat 内部可见的路径：

```yaml
services:
  bridge:
    volumes:
      - ./data/shared:/shared
  napcat:
    volumes:
      - ./data/shared:/shared
```

上述是追加挂载片段，需合并进已有 Compose 服务，保留原来的运行时和数据挂载。
本地桥接连接容器 NapCat 时，本机可能看到 `D:/qq-shared/probe.txt`，
NapCat 看到 `/shared/probe.txt`；对应文件 URL 应为 `file:///shared/probe.txt`。
已有图片命令也接受 `base64://` 或 NapCat 可访问的 HTTP URL。
默认部署不会自动推断另一进程的磁盘映射。

两端的 `bridge-portability-test.mjs` 各通过以下 8 项：

1. 真实桥接连接 NapCat，状态文件 PID 与子进程一致，聊天白名单为空。
2. 真实 NapCat 返回版本、在线状态及图片能力。
3. 带空格和特殊字符的共享文件，按 NapCat 命名空间的文件 URL 被接受。
4. 未映射的进程本地文件 URL 被 NapCat 拒绝。
5. 管理员通过真实 DSH 工具读取提示中未透露的随机标记，写回完全相同的文件字节。
6. 停止桥接并删除输入、输出文件后，重启保留同一管理员会话，模型凭对话记忆恢复标记。
7. 普通白名单用户使用独立的 chat-only 会话。
8. 陌生人被实际处理并拒绝，没有回复，也没有创建会话。

管理员工具与续聊使用现有 `danger-full-access` 路径，工作目录和 DSH home 均隔离。
这不是操作系统沙箱测试。专属共享测试目录、桥接子进程和临时 home 已清理。
临时暂停的 AstrBot 已恢复；NapCat 配置恢复后 SHA-256 与备份一致，临时代理容器已删除。

真实协议测试仅连接和调用状态、版本、媒体能力及专属测试文件的 API。
消息与模型测试使用独立合成 OneBot，不向真实联系人或群发送消息。
因此它们分别证明协议兼容、模型链路与磁盘访问，真人 QQ 完整收发和长期运行仍需实际验收。

## 复现

不需要 QQ 登录或模型凭据：

```powershell
node tests/docker-test.mjs
docker build --no-cache --pull -t qq-dsh-bridge:verify .
node tests/docker-runtime-test.mjs qq-dsh-bridge:verify
node tests/export-public-test.mjs
```

真实 Docker 模型运行方法见 [Docker 验证报告](Docker验证报告.md#复现)。
新的跨平台测试使用同一脚本，服务和挂载由运行者准备：

```powershell
$env:DSH_VERIFY_COMMAND = 'D:/dsh-runtime/node_modules/@deepseek-ai/dsh/lib/bin.js'
$env:DSH_VERIFY_CREDENTIALS_FILE = Join-Path $env:USERPROFILE '.dsh/.credentials.yaml'
$env:QQ_VERIFY_ONEBOT_URL = 'ws://127.0.0.1:3001'
$env:QQ_VERIFY_ONEBOT_TOKEN = '<测试端点的token>'
$env:QQ_VERIFY_SHARED_ROOT = 'D:/qq-shared'
$env:QQ_VERIFY_NAPCAT_ROOT = '/shared'
$env:QQ_VERIFY_RESULT = 'state/portability-native-results.json'
node tests/bridge-portability-test.mjs
```

端点必须是已登录 NapCat 的正向 WebSocket；共享目录必须已存在，且 NapCat 可见。
Linux 使用相同环境变量，填写各自命名空间内的绝对路径；容器另需只读挂载
`tests/`、对应平台的 DSH 运行时及凭据，并给测试结果和共享目录写权限。
测试会产生真实模型调用；结果只记录检查项，不输出凭据、账号和聊天内容。

本轮原始结果保存在 Git 忽略的 `state/`，未将机器路径、认证输入和运行日志提交：
`portability-native-results.json`、`portability-docker-results.json`、
`clean-napcat-restoration.json`、`docker-fixture-results.json`、
`docker-runtime-results.json` 及 `test-log/fresh-clone-local/final-summary.json`。
