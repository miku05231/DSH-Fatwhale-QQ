# QQ-DSH v3.4.0-beta.1

v3.4.0-beta.1 把消息核心收进 DSH 进程，作为可选开关。默认仍然是 v3.3.0 的独立进程，所以现有 NAS Compose、托盘和 `node src/index.js` 的行为不变。Compose 的服务、端口和启动命令也没有改。

- 新配置 `bridge.runMode`：`standalone`（默认）或 `embedded`。
- `standalone`：插件页继续挂 `/qq-bridge/`，启动按钮仍然拉起桥接子进程。
- `embedded`：companion 在 Cordis 插件生命周期里调用 `startBridge({ embedded: true })`。OneBot、收发、管理员的 DSH 调用和 `/qq-bridge/` 控制台都在宿主进程里。不再启动桥接子进程，管理员请求也不再绕回本机 companion HTTP。
- 普通成员的无工具聊天仍走原来的独立子进程。管理员名单和工具策略没有放宽。
- NapCat 断线按原来的退避重连。配置错误、连接失败和消息处理里抛出的异常留在插件里，不会让 DSH 退出。插件卸载或重载时关掉 WebSocket、定时器和监听器。
- 健康检查和插件页会显示 `embedded`、是否连上 NapCat，以及最近一次错误。
- 启用方式：在 `config.json` 写 `"bridge": { "runMode": "embedded" }`，或执行 `node tools/install-companion.mjs --run-mode embedded`。插件补丁里的 `runMode` 优先于配置文件。改完要完全重启 DSH。全新 `dsh web` profile 的 `cordis.patch.yml` 如果是空序列 `[]`，安装器会先去掉它再写入列表，避免拼出非法 YAML。
- 宿主进程结束，进程内的 QQ 桥也会停。需要一直在线时用 `dsh web`，不要依赖会随窗口关闭的 Desktop。

本版仍声明兼容 DSH 0.2.2-rc.1 与 0.2.1-rc.5。没有连接真实 QQ，也没有改 NAS 上正在跑的容器。
