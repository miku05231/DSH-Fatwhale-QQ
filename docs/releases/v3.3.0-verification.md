# v3.3.0 发布前验证记录

日期：2026-11-11。本文记录发布前的本地隔离检查；正式构建、安装检查及发布结果以 [v3.3.0 发布流水线](https://github.com/miku05231/DSH-Fatwhale-QQ/actions/workflows/release.yml) 和 [Release](https://github.com/miku05231/DSH-Fatwhale-QQ/releases/tag/v3.3.0) 为准。

## 候选与运行方式

- 基于公开 main `77134f84c65d56445a89b7615f92da3d82a10aae`，项目版本 `3.3.0`，完整 companion `0.3.0`。
- 完整 bundle 明确配置 `runMode: embedded`，启用后自动在 DSH 宿主进程内启动桥接核心；管理员直达同一宿主 prompt，普通成员继续隔离 chat-only 子进程。旧命令行或 server-only 未指定模式时保留 standalone 兼容。
- 移植了运行模式、控制器、管理员调用及清理接口，并补足并发停止、迟到启动收尾、取消活动任务和停止后状态防回写。插件 HUD 与完整控制台的桥接启停均使用共享控制器。
- 测试使用公开源码镜像、临时 HOME／配置／状态和本机模拟 OneBot／模型，不读取真实 QQ 联系人或私人模型凭据。Windows；首轮 Node.js `24.19.0`，定向复跑 `24.20.0`，浏览器专项使用真实 Edge。
- Docker 只可作为 NapCat 的部署方式；DSH 在宿主常驻，桥接随其插件运行。本版不安排桥接／DSH 容器或 NAS 构建。

## 失败历史与复验边界

首轮 embedded 专项在 20 项后因共享测试 helper 缺少 `liveCount()` 中断。补充只读计数方法后，33 项处又发现模拟消息误投给第二个探针连接；测试明确选择桥接 socket 后，仅复跑该专项并 45/45 通过。配置入口及日志测试首次均退出 0，只有任务 runner 的成功输出匹配不符，修正 runner 后分别复跑 8/8、9/9。上述失败与复验原始报告均保留；只调整夹具、共享测试 helper 和任务 runner，没有改动产品迁就测试。
