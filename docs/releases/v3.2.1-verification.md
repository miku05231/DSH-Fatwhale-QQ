宿主 Node 为 24.16.0，桥接镜像 Node 为 22.23.2；DSH 回归核心固定 0.2.0-rc.2。常规桥接镜像已真实构建和运行；NAS Dockerfile 的版本标签与 Compose 通过静态检查，本版没有重做完整 NAS 镜像构建或 NAS 部署。

## 同日 AstrBot 与 DSH 基线

修复前同日基线已完成固定 AstrBot 4.29.3 / Python 3.12.10 / APScheduler 3.11.3 的 50 项 Python 检查，以及原生消息、媒体、权限、模型工具循环和四个锁定上游样本的基础命令。

受控专项覆盖普通提醒在 worker 冷重启后恢复投递、创建者与原会话保留、跨群拒绝与旧来源失效；天气覆盖本地 API 查询、每日定时发送及授权创建、撤销、配置重存与整代回退后的失效。真实 DSH 0.2.0-rc.2 容器消息往返与普通成员无工具请求也已检查。

这些基线来自 v3.2.0 源码，不能计作 v3.2.1 的重复专项验收；本版没有更换上述运行时、插件源码或调度实现。

## 未覆盖范围

- 未新增真实 QQ 文字、图片、语音或定时投递验收；主动发送使用隔离收集器。
- 未调用真实模型供应商或公开天气 API。
- 未全面覆盖 Windows 从零安装、长期运行、休眠、网络变化、其他 CPU 架构与全部 AstrBot 插件。
- 普通提醒仅限 is_task=false；任务提醒、撤权后第二次原生 timer 及授权页面与原生 runtime 的完整联调不在通过范围内。
- GitHub 发行工作流仍须在 Linux 和 Windows 完成其检查、构建和实际便携包安装，全部通过才创建正式 Release。
