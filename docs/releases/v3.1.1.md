# QQ-DSH v3.1.1

本版包含 v3.1 的模型同步、QQ 登录检测和启动恢复修复，并隔离 Windows 云端进程控制测试的 PowerShell 模块环境。运行要求为 Node.js 22+。

## 模型与登录修复

- 连续多轮复用同一会话时，控制台保存的合法模型与思考档位在下一条 QQ 消息生效，已打开的 DSH 对话页同步显示选择；无需重建会话。
- 按模型能力校验思考档位，分别展示目标、实际、待应用与失败。显式选择失败时报告错误，在途任务和已接收任务不重复回退执行。
- 从实际持久事件记录模型回执，修复恢复会话和重复 header 的档位继承，不改桌面全局默认模型。
- 使用 NapCat WebUI 和已鉴权 OneBot 查询 QQ 实际状态，改进本安装进程识别、保存账号恢复、端口冲突处理及跨启动日志归档。
- 新增脱敏健康记录；原始 NapCat 日志及业务日志仍作为本机私有数据保管。保留本机配置、会话、人格、记忆和自定义工具。

## 发布修正

v3.1.0 的 Windows 自动构建因 PowerShell 子进程超时被阻止，没有生成正式 Release。本版保留该历史标签。云端探针发现首次内置命令查询耗时超过 31 秒，模块路径包含机器级 Azure、SQL Server 等目录；本版限制测试子进程只使用对应 PowerShell 自带的模块目录，在就绪信号前显式加载所需内置模块，分别设置启动 60 秒和命令执行 15 秒期限。测试临时根目录统一为实际长路径，避免与 .NET 的路径表示不同。新增模块隔离、路径一致性和命令超时回归，以及专门的 Windows CI；全部业务断言保留。快速模型、控制台与 NapCat 检查移至较慢的安装器测试之前。

## 验证范围

模型修复已通过真实隔离 Electron 24/24、DSH Web + Edge 19/19、companion 55/55 和独立宿主 13/13。Windows 进程控制本机与云端专项均 10/10 通过，包含新增的超时、模块隔离和路径一致性检查；其他专项与发布结果见 [v3.1.1 验证说明](../verification-v3.1.1.md) 和对应标签的 GitHub Actions。

真实 QQ 仅进行只读在线检查及一次 NapCat 重启后的快速登录恢复。真实文字/语音投递、完整工作日、网络切换、休眠、用户注销恢复、本版 Docker 和其他系统尚未全部验收；登录身份失效的具体触发原因仍未确定，不承诺永久免重新授权。

## 安装与升级

Windows 用户下载 `qq-bridge-3.1.1-portable-win64.zip`，或在控制台“系统 → 应用更新”检查并确认安装。另有 `qq-bridge-3.1.1-source.zip`、`qq-bridge-launcher-3.1.1.exe` 和 `SHA256SUMS.txt`；独立 EXE 需要配合完整工程。

升级保留本机数据。任务空闲时正常退出并重启 DSH，以加载新的 companion；自动更新器不会终止 DSH。模型同步发生在下一条 QQ 消息提交时，保存操作不立即修改所有打开的桌面对话。
