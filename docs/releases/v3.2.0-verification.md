# QQ-DSH v3.2.0 匿名验收摘要

本摘要只记录受控验证结果，不包含内部验收中的用户标识、群号、主机地址、私有路径、访问令牌或运行时刻。它说明了已覆盖的场景，不构成完整测试或通用兼容认证。

## 已完成的受控验证

- **AstrBot 固定样本：**四个固定上游样本在 Windows 与 NAS 各通过 4/4 检查，每端覆盖六条基础命令。实际安装和加载的源码与冻结样本一致；这不等于每个样本的全部功能均通过。
- **普通提醒：**两端均验证 worker 冷重启后的普通提醒恢复、创建者与原会话保留、跨群拒绝，以及过期来源回调拒绝。范围仅为 is_task=false；没有额外等待撤权后的第二次原生 timer。
- **天气定时授权：**两端原生 scheduler 均完成受控每日触发并向获准目标发送纯文本。无授权、显式撤销、配置重存和整代回退后的旧授权或回调均按预期拒绝。查询与意图分类使用受控服务，不是公开天气 API 或真实模型。
- **DSH 0.2.1-rc.5：**Windows 与 NAS 各 5/5 受控兼容检查通过，覆盖 SSE 文本、工具结果、PNG、取消操作及 CLI 检查。使用 loopback 受控接口；生产 DSH 核心仍为 0.2.0-rc.2。
- **日志页面：**本机合成浏览器检查 13/13；本机和 NAS 升级后也检查了实际页面。概览连续三次轮询及系统页日志读取均返回 HTTP 200 / no-store，NAS 来源分别为 bridge-daily 与 napcat-webui。请求间隔包括完成后约三秒等待和请求耗时；这些检查不构成真实 QQ 新适配投递验收。
- **天气授权页面：**浏览器检查 16/16，使用真实页面和 HTTP 路由，但 manager 与 policy 使用内存替身；没有把它计作授权页面和原生 runtime 的一体联调。
- **便携更新 helper：**Windows 隔离更新器套件 61/61 通过，覆盖 runtime 锁文件、样本、AstrBot 源文件、许可证和 notices 的安装，保留 `runtime/python/`、`runtime/venv/` 与本地 runtime 数据，并在注入中途失败后验证恢复和新文件移除。另用当前打包器与启动器在系统临时目录生成便携测试包，通过真实 PowerShell 安装流程运行 84 项断言：当前 helper 安装 runtime 文件并保留用户数据；v3.1.5 冻结 helper 和未修改的 v0.2.3 helper 均在 staging/backup 前拒绝 runtime 包，且配置、状态、日志、NapCat 配置及其他本地文件保持不变。v3.1.5 helper 来自提交 `91ab30b3aa5b2a5b2a4934e913e771ce4dfafa43`，SHA-256 为 `326c1fb1f06aecc32e9335e175e12ed14e4b1cd3fb9b9beabd2c216abcc7fee4`。临时测试包不替代发行流水线对最终 ZIP 的安装校验；Release 创建以该流水线通过为前提。

## 未覆盖范围

- 本版没有新增真实 QQ 消息投递验收。此前的 8/8 来自边界测试插件，不能代表四个上游样本或生产 QQ 投递。
- 本版未调用公开天气 API或真实模型供应商；天气与模型有关的通过结果来自受控服务。
- 本轮复用既有运行时，没有重做从零安装；未覆盖所有 AstrBot 插件 API、任意外部依赖、所有系统和架构。
- 普通提醒之外的“任务”功能、撤权后第二次原生 timer、授权页面与原生 runtime 的完整联调不在通过范围内。
- 生产 DSH 核心仍保持 0.2.0-rc.2；0.2.1-rc.5 的结果仅为受控双端兼容检查，不代表生产已升级。

## 便携更新迁移边界

- 旧版 helper 对 `runtime/` 路径的拒绝是有意保留的历史行为。离线检查的 v3.1.5 便携包会从安装目录复制其 helper 到更新任务；该 helper 不接受 `runtime/`，因此不能直接安装含 runtime 文件的 v3.2.0 包。helper 会在创建 staging 和 backup 前拒绝归档，原应用文件不变。
- 当前 helper 只接受 `runtime/astrbot-lock.json`、`runtime/astrbot-samples.json`、`runtime/astrbot/` 及其子路径，不接受生成式 `runtime/python/`、`runtime/venv/` 或其他 runtime 根路径。以上隔离安装结果不会替代真实 v3.2.0 发行 ZIP 验收。
- 建议下载并校验完整 v3.2.0 便携包，解压到新目录，逐项迁移明确需要的配置和用户数据，并检查其中的绝对路径、本机补丁及 NapCat 配置。不要盲目覆盖旧目录，也不要整目录复制生成式 `runtime/python/` 或 `runtime/venv/`；需要的 AstrBot 用户数据应单独确认后迁移。保留旧目录，直到新目录验证完成。该跨目录数据迁移流程尚无完整端到端验收，也没有旧控制台的自动迁移入口。
