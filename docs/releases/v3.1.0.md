# QQ-DSH v3.1.0

修复连续多轮复用会话时的模型切换，并改进 NapCat 登录检测、启动恢复和日志保留。运行要求保持 Node.js 22+。

## 模型切换

- 保存合法模型后，下一条 QQ 消息继续使用原会话，应用新的供应商、模型与思考档位；已打开的 DSH 对话页同步显示选择，无需刷新或重建会话。
- 控制台按实际模型能力提供思考档位，非法组合保存失败且保留原配置；未知能力明确等待宿主校验。
- 显式选择失败会报告错误，不再继续用旧模型作答或回退到另一宿主重复执行。控制台分别显示已保存目标、最近实际使用、待应用和失败。
- 在途消息保持原配置，排队的下一轮使用新配置。修复恢复会话、跟随/手动模式往返及重复请求 header 时实际档位回执丢失的问题，不修改桌面全局默认模型。

## QQ 状态与恢复

- 使用当前 NapCat WebUI 鉴权及已鉴权 OneBot 后备查询实际 QQ 状态，区分在线、离线、需登录、初始化、未知和停止；不再把端口开放或旧状态文件当作已登录。
- 启动器核对本安装的实际入口与 worker，优先使用保存的自动登录账号。旧端口被占用时继续尝试启动，必须核对监听进程后才报告控制台就绪。
- 重定向前归档 NapCat 原始日志，控制台持续保存脱敏健康记录。新增健康记录不记录账号、二维码、聊天正文或鉴权凭据；NapCat 原始日志和桥接业务日志仍需按本机私有数据保管。
- 保留本机配置、登录数据、人格、记忆、会话和自定义工具；本机调查记录与私人辅助脚本不进入公开源码包。

## 验证范围

真实隔离 Electron 24/24、DSH Web + Edge 19/19、companion 55/55、独立宿主 13/13 通过；另完成模型能力、控制台、NapCat 状态、Windows 启动器和包装回归。真实 QQ 仅作只读状态检查，并确认一次受控 NapCat 重启后可快速登录，无需再次扫码。

**尚未完成**：真实 QQ 消息投递、完整工作日登录稳定性、网络变化、休眠和 Windows 用户注销恢复，以及本版真实 Docker 和其他操作系统验证。登录身份曾失效的具体触发原因仍未确定，本版不承诺永久免重新授权，也不自动开启登录后自启。语音和平台自动化沿用旧版的未实测范围。

完整测试与边界见 [v3.1.0 验证说明](../verification-v3.1.0.md)。正式构建和发布结果以对应标签的 GitHub Actions 为准。

## 安装与升级

Windows 用户下载 `qq-bridge-3.1.0-portable-win64.zip`，或在控制台“系统 → 应用更新”检查并确认安装。源码用户可使用 `qq-bridge-3.1.0-source.zip`；单独的 `qq-bridge-launcher-3.1.0.exe` 需要配合完整工程。`SHA256SUMS.txt` 提供三个文件的 SHA-256。

升级会保留本机数据。已运行的 DSH 宿主需要在任务空闲时正常退出并重新启动，才能加载新的 companion 代码；自动更新器不会代替用户终止 DSH。同步发生在下一条 QQ 消息提交时，保存操作不立即修改所有打开的桌面对话。
