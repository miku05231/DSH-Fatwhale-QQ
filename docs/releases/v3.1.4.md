# QQ-DSH v3.1.4

v3.1.4 汇总了 NAS Docker 部署、局域网媒体接口、文件交付与几项可靠性修复。运行要求仍为 Node.js 22+。

## Docker / NAS

- 新增 NAS 专用的 Dockerfile、Compose 与带登录保护的控制台网关。控制台、桥接和 NapCat 使用隔离网络；
  第三方 NapCat 容器不能直接访问无认证的桥接端口。
- 支持把宿主机或 NAS 文件区只读挂载进桥接，并通过共享 outbox 交给 NapCat 读取。
  `upload_private_file` / `upload_group_file` 接受桥接视角和 NapCat 视角两种路径；目录、越界路径和超过 200 MiB 的文件会被拒绝。
- NAS 文档使用通用占位路径，不包含个人网络拓扑或凭据。

## 媒体

- 生图支持 ComfyUI 异步代理、OpenAI、硅基流动和自定义 OpenAI 兼容服务；TTS 支持 Edge、OpenAI、硅基流动和自定义兼容服务。
- 两类接口都支持可选 Bearer 密钥、自定义 `baseUrl`（可含 `/v1` 或代理前缀）与 WAV / MP3 等媒体格式。
- Linux / 容器中的 DSH 状态改为检测按需运行时，而不是查找 Windows 进程名。控制台会显示“按需运行”、版本和实际入口。
- 新增可选的合成前翻译和独立语音语种设置；翻译失败时保留原文，不把未翻译文本送入 TTS。

## 文件与可靠性

- 修复文件上传策略被重复执行的问题，统一由一次策略检查决定是否跳过、改写或放行。
- 文件复制使用原子写入并限制 outbox 保留数量，避免重复文件和无限增长。
- 更新器仍只在用户确认后安装，校验 SHA-256，保留配置、人格、记忆和本机数据。

## 验证与范围

Docker 静态检查 104 项通过；NAS 上的控制台认证、QQ 在线、OneBot 连接、DSH 实际回复与私聊文件上传已实测。

未新增真实 QQ 长期稳定性、真实付费云服务、Docker 跨架构或 macOS 验收。局域网 API 的可用性取决于目标服务是否监听且 NAS 能访问对应端口。

## 安装

Windows 下载 `qq-bridge-3.1.4-portable-win64.zip`，或在控制台“系统 → 应用更新”检查并确认升级。
源码目录可直接 `git pull`，Docker 部署按 `docs/Docker部署.md` 重建镜像。
